# Kridens Alias — требования к проекту

Свой "Алиас" для тренировок. Главная цель — решить проблему несбалансированной сложности слов в существующих реализациях игры.

## Режимы игры

1. **Одиночный (single-device)** — все играют с одного телефона, передают его по кругу.
2. **Мультиплеер (комнаты)** — один создаёт комнату (код), остальные подключаются со своих устройств; синхронизация состояния хода/таймера/очков через сервер.

Оба режима используют одно и то же ядро балансировки слов — деки собираются одинаковым алгоритмом, разница только в способе показа слова и синхронизации.

## Платформа и стек (v1)

- Клиент: веб-приложение (PWA), с прицелом на то, что позже его можно обернуть в нативное приложение (Capacitor/React Native) без переписывания игровой логики — то есть игровое ядро (балансировка, деки, состояние хода) должно быть отделено от UI-слоя.
- Сервер: свой WebSocket-сервер (Node.js) — держит комнаты, синхронизирует ход/таймер/очки между участниками, раздаёт деки.
- Одиночный режим может работать полностью на клиенте без сервера (offline-friendly), используя тот же алгоритм балансировки.

## Проблема, которую решаем

В обычном Alias слова выпадают без учёта сложности — команде может не повезти с чередой сложных слов подряд, или наоборот, повезти с лёгкими. Нужна механика, которая гарантирует **сопоставимую суммарную сложность** того, что достаётся каждой команде за ход/игру, а не просто случайный порядок.

## Модель слова

Каждое слово/словосочетание — запись:

```
{
  "text": "дисперсия",
  "category": "noun",        // noun | phrase (расширяемо позже)
  "weight": 3,                // 1..5, целое
  "source_freq": 0.4,         // ipm или иная сырая метрика, для аудита
  "status": "approved"        // approved | pending | rejected
}
```

Шкала веса: **1–5**, где 1 — самое частое/бытовое слово ("вода", "стол"), 5 — редкое/специальное ("дисперсия", "аннексия"). Пять уровней дают более плавную градацию, чем 1–3, но остаются вручную обозримыми при курировании.

Категории на старте: `noun` (нарицательные существительные) и `phrase` (устойчивые словосочетания — идиомы, коллокации типа "куриная слепота", "белая ворона"). Схема данных сразу поддерживает добавление новых категорий (глаголы, персонажи, фразы-действия) без миграции.

## Пайплайн сборки словаря

1. **Сырой список.** Собираем кандидатов — нарицательные существительные и устойчивые словосочетания русского языка (источники: частотные словари, тематические списки, ручные добавления).
2. **Авто-вес по частотности.** Берём частотную метрику на слово. Рекомендуемый источник — библиотека `wordfreq` (Python, поддерживает `ru`, построена на корпусах Википедии/новостей/субтитров) или частотный словарь Ляшевской–Шарова (на основе НКРЯ). Поисковая выдача (Google/Yandex hit count) не годится как источник — не API, не стабильно, легко банят.
3. **Биннинг в вес 1–5.** Частотность распределена по степенному закону (log-scale), поэтому весовые бины делаем по логарифму частоты, не по линейным порогам — иначе почти все слова упадут в один бин.
4. **Экспорт на ручную курацию.** Выгружаем в CSV: `text, category, source_freq, auto_weight, weight, status, comment`. `weight` — редактируемая копия `auto_weight`, которую ты правишь руками (частотность может обманывать: слово частое, но неудобное для объяснения — как раз твой пример с "дисперсией"; или наоборот, отфильтровать мусор — аббревиатуры, нецензурщину, слишком узкие термины).
5. **Импорт обратно.** Причёсанный CSV/JSON — единственный источник данных, который использует приложение. Пересборка сырого словаря — отдельный офлайн-процесс, не часть игры.

## Механика сборки деки на ход

Не жёсткая ротация "1-2-3-1-2-3" — она даёт нечестное распределение, если слово не объяснили вовремя. Вместо этого:

- Дека на ход — фиксированное количество слов N (например, 10), выбранных так, чтобы **сумма весов** укладывалась в целевой диапазон (например, target = N × 3, допуск ±2). Комбинация весов внутри деки может быть любой (3+3+3+..., или 1+2+5+4+..., без разницы) — важно, что суммарная сложность у всех деки одинакова.
- Внутри деки порядок весов перемешивается случайно, с мягким правилом "не давать два веса 5 подряд", чтобы не было полосы невезения в начале хода.
- Слова не повторяются в рамках игровой сессии, пока не закончится пул — потом можно либо завершить игру, либо начать новый "заход" с полным сбросом пула.
- Алгоритм детерминирован относительно seed — то есть при желании можно воспроизвести конкретную деку (полезно для отладки/тестов), но по умолчанию seed случайный.

Этот алгоритм — общий для одиночного и мультиплеерного режима; в мультиплеере сервер является единственным источником truth для сгенерированной деки (генерирует и раздаёт, чтобы никто не мог подсмотреть у себя в devtools).

## Что ещё нужно зафиксировать перед началом разработки

- Целевой объём словаря для v1 (сотни слов? тысяча+?).
- Правила игры: длительность хода, число ходов на игру, штрафы за пропуск слова, система очков.
- Состав команд (сколько команд, сколько игроков в команде — важно для мультиплеера/комнат).
- Фильтр на нецензурную/чувствительную лексику при кураций словаря.
